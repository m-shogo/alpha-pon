# 投資判断の学習・再発防止ログ
更新: 2026-11-18
目的: 同じ誤解・確認漏れ・根拠のない推薦を繰り返さず、次回の調査と判断を改善する。
正本: [希望と役割](user-preferences.md)。このログは失敗と改善を記録し、希望の重複コピーを作らない。

## 判断の種類（必須）
- NEW: 本人が新しく決めた目的・希望・制約
- CORRECTION: 従来からの希望について、助手側の理解が間違っていた修正
- CHANGE: 本人が従来の決定を明示的に変更
- HYPOTHESIS: 助手の提案・未検証の仮説（本人の希望ではない）
- VERIFIED: 一次情報や実データで確認した事実（確認日と出典が必要）
- UNKNOWN: 未確認・確認不能

CHANGE は以前の方針と新方針の差分、変更理由、本人の発言根拠を残す。CORRECTION を CHANGE と呼ばない。

## 次回の実行順（回答前チェック）
1. 対象リポジトリ・ブランチ・正本を特定し、過去の決定と現状を確認。
2. 問いの種類を区別: 優待株の買い時 / 発掘株の探索 / 一般的な相談。
3. 事実・本人希望・助手仮説・未確認を区別。現在価格と一次情報を照合。
4. まず質問に直接答え、判断根拠・反対材料・見送り条件・機会費用を提示。
5. 新規決定・認識修正・方針変更があれば正本を更新。失敗があれば「原因→防止策→次回の検証」をこのログへ。
6. 変更コミットを確認し、次回に改善できたか実績で検証。保存だけで解決とみなさない。

### なぜそうしたか（推定と限界を区別）
- **確認の省略 / 作業順序の誤り（行動として確認できる）**: 既存GitHubの正本・研究・学習ログの調査範囲が不足していた。文書作成という即時に完了を示しやすい作業を、検証より先に選んだ。
- **要望理解の失敗（会話で確認できる）**: 「利益目的の発掘」と「優待目的の放置株」を同じ資産配分問題として扱った。本人の目的変更と助手の認識修正も混同した。
- **完了基準の誤り（行動として確認できる）**: GitHubへのコミット成功を改善完了に近い表現で報告した。再発防止の実証テストは行っていない。
- **自己検証の不足（行動として確認できる）**: 前回の指摘を次の回答前に照合しなかった。既存ルールが機能していないことを自発的に検知できなかった。
- **「サボったか」について**: 行動として必要な確認・検証を省略したことは事実。意図的な怠慢や内部動機を確証なく断定できない。「時間がなかった」等の弁解で片づけない。
- **能力・環境上の限界**: GitHubに書いた文書は別の会話・実行で自動ロードされない。したがって「書けば次から必ず覚える」は成立しない。実行経路への接続が必要。
