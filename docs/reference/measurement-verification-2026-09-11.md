## 3. イベントスタディ ↔ 手計算

引け後提出（＝翌営業日反応）の例を選んだ。境界が一番ずれやすい。

```

手計算  raw=-46.45bps benchmark=+84.06bps abnormal=-130.51bps
実装    raw=-46.45bps benchmark=+84.06bps abnormal=-130.51bps
  差 = 0.000000000bps
```

**この照合の過程で欠陥を1つ見つけた**（#2069）。ユニバース指数が
`open === close` で、建玉日の日中の市場変動が銘柄側にだけ入っていた。
指数に始値の水準を持たせて直した。

## 4. backtest のコスト・単元株 ↔ 手計算

「儲かるか」を決める部分。

```
対象: am-14070-2025-10-06 / 建玉 2025-10-07 始値 1773 / 決済 2025-10-15 終値 1776

単元数     floor(1,000,000 / (1773×100)) = 5        → 実装 5        ✓
約定金額   5×100×1773 = 886,500円                   → 実装 886,500  ✓
参加率     886,500 / 775,688,710(20日平均売買代金) ×100
           = 0.11428553601096%                      → 実装 同値     ✓
gross      (1776/1773-1)×10000 = 16.920473773265bps → 実装 同値     ✓
benchmark  -158.431473920992bps                     → 実装 同値     ✓
コスト     手数料5×2 + スプレッド(10/2)×2 + スリッページ8×2
           + market impact 10×0.114286×2
           = 10 + 10 + 16 + 2.2857 = 38.2857107202192 → 実装 同値   ✓
net alpha  175.351947694258 − 38.2857107202192
           = 137.0662369740388                      → 実装 同値     ✓
```

**最初は2箇所ずれた。どちらも私の仮定が間違っていた。**

- 参加率の分母を「建玉日の株数」と思っていたが、実装は
  **20日平均の売買代金（円）**。こちらが正しい
- スプレッドを往復で全幅×2 と思っていたが、実装は
  **片道で半値幅**（往復で全幅1回ぶん）。市場慣行として正しい

## 検証しても消えない限界

- **対照群がない。** EDINET のイベントスタディは帰無仮説「異常収益=0」を
  見るだけ。規模・業種でそろえた対照は未実装

  実際の約定で測り直していない。紙トレード帳簿がそのために用意してある
