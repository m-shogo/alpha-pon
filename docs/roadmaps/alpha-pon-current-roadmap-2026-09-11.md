## 4. 実データを流して分かった測定上の落とし穴

合成データでは全部通っていた。**3つとも候補件数を見ても気づけない型。**
詳細は前版の 0-C。

| # | 落とし穴 | 効き方 |
| --- | --- | --- |
| 1 | 株式分割を暴落として検出 | 189営業日で -25%以下が470件、大半が分割 |
| 2 | 非流動銘柄が候補を埋め尽くす | 4,321銘柄 1,775件 → 流動830銘柄 432件 |
| 3 | ETF ベンチマークが β を一様に希薄化 | 平均β 0.59 → ユニバース等加重で 1.00 |
| 4 | **書いたのに誰も呼んでいない** | 実行層3本・検査2本・リセット関数。CI で検査するようにした |
| 5 | **CI にデータが無い検査は永久に緑** | 価格・開示の保存庫は .gitignore。日次へ移した |
| 6 | **設定した値が効いていない** | 間隔20秒のつもりで3秒。状態を import 時に作っていた |
| 7 | **封印を bundle 側から狭められる** | 正本 2025-07-01 が 2026-03-01 に縮んでいた |

**順序が要る。** 2と3を先に潰さないと、市場モデルを入れるほど候補が増える
（553件 → 1824件）。

### 自分を騙しかけた記録

ユニバース指数に替えたら暴落日の候補が 0 件になった、と一度結論しかけた。
確認すると **809銘柄すべてで β が推定できていなかっただけ**だった。

**「候補が減った」は成果ではない。** 減った理由が「説明がついた」なのか
「測れなかった」なのかを必ず分ける。CLI は `market_model_unavailable` の
件数と横断βの平均を常に出し、平均βが 1 から 0.25 以上離れたら警告する。

### 4〜7 に共通する形（2026-09-11 夜）

どれも **「実装した」と「動いている」を取り違えた**ことが原因。
コードはある。テストも通る。ロードマップには ✅ と書いてある。
それでも本番では一度も実行されていない、あるいは設定が効いていない。

  - 到達性を機械で検査する（`scripts/verify-src-reachability.ts`）。
    **テストからの import は到達とみなさない。** テストが通ることと
    本番で動くことは別
  - 到達可能でも「対象を見たか」は別問題。検査が実際に何件を見たかを出力させる
  - 設定を入れたら、使われたことを**別の観測**で確かめる（書き込み時刻の間隔など）。
    「表示しているから効いている」は根拠にならない

## 6. 消えない制約: 84日遅延

`toBacktestPriceSeries` は `executable` 境界を使うので、
`retrievedAt` / `firstExecutableAt` が `asOf` を超える行は選ばれない。

**J-Quants Free の価格でリアルタイム売買はできない。**
検証（過去の計測）には何の支障もないが、⑥監視 と ⑦通知 を
「今日の該当銘柄」として動かすには**別系統の気配値が要る**。

これは有料化の第一候補。ただし **Edge が確認できるまで課金する理由が無い**。
順序は「検証 → Edge 確認 → 気配値を買う → 執行」。

## 8. 維持する原則

- 未確定日時を捏造しない
- 原因を名乗れないときは名乗らない（`unknown` で残す）
- SNS・掲示板を signal source にしない
- 件数が少ない学習結果で強い判断をしない
- 自動でルールを削除しない（提案のみ）
- holdout を早期に開けない
- **「候補が減った」を成果と読まない。減った理由を必ず分ける**
- **取得したものはまず保存してから使う**（保持期間の短いソースは特に）
