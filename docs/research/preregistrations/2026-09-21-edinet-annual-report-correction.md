# 事前登録: 有価証券報告書の訂正を出した会社は、そのあとアンダーパフォームするか

- 登録日: 2026-09-21（**この母集団のリターンをまだ見ていない時点**。このファイルのコミット時刻が証拠）
- edgeId: `edinet-doc:訂正有価証券報告書`（新しい Edge。既存の Edge の別条件ではない）
- specId: `edinet-document-event-study-v1`
- 期間: **研究期間 2024-06-19 〜 2025-06-30**（封印は開けない。これは研究期間の測定）

## なぜこれを測るか

ユーザーの挙げた Edge 候補は「サンリオの業務に関係ない不祥事」「バイトテロ」で、
それらは TDnet の適時開示にしか出ない（`docs/reference/edinet-reason-codes-2026-09-11.md` で確認済み）。
TDnet の保存は 2026-08-03 からで、封印のため**測れるのは 2027-08 頃・1回だけ**。

EDINET は 2024-06-19 から保存してあり、研究期間を丸ごとカバーする。
臨時報告書の事由に不祥事は出てこないが、**訂正有価証券報告書**は会計・開示の問題を示しうる。
「不祥事そのもの」ではなく**会計・開示の問題の代理指標**として、いま測れるものを測る。

同じ発想で訂正内部統制報告書も数えたが、研究期間で流動性の母集団に入るのは
19 反応日しかなく、最小クラスタ 20 に届かないので**測らない**（件数だけ数えた。リターンは見ていない）。

## 母集団（値動きを条件にしない）

1. EDINET の保存行で、書類種別の説明が **`訂正有価証券報告書`** で始まるもの（先頭一致）
   - 「訂正内部統制報告書」「訂正有価証券届出書」は**含まない**（先頭一致で外れる）
2. 5桁コードにできる上場銘柄。提出時刻があること
3. 反応日 = 提出が引け前なら当日、引け（15:30・2024-11-05 以前は 15:00）以降なら翌営業日
4. 同じ (銘柄, 反応日) は1件にまとめる
5. **同一銘柄は 60暦日以内の2件目以降を数えない**（訂正は数日〜数週つづけて出るため）
6. 流動性は**反応日を含む直近20本**の平均売買代金 5億円/日以上（既存の CLI と同じ）
7. ETF 等（33業種 9999）は除外

数えた件数（リターンは見ていない）: 研究期間の訂正有価証券報告書は
**896件 / 487社 / 194日**、(銘柄,日) の重複を除いて 555件。

## 測ること

- 市場モデル（等加重ユニバース指数）調整後の異常収益。**コスト控除前**
- horizon: D+1 / D+5 / D+20 / D+60、**主要は D+20**
- **両側**（下がるとは決めつけない。会計の訂正が既知の悪材料の確認なら反応しないこともある）
- クラスタは反応日（同じ日のイベントは1つとして数える）

## 合否

- **主要 D+20 のクラスタ補正後 |t| ≥ 1.96** なら「向きのある反応がある」
- ただし**最小クラスタ 20**。反応日が 20 に満たなければ、t が大きくても標本不足として
  「反応なし」で記録する（2 クラスタから |t| = 396 が出た。合成データの試験）
- 閾値は試行台帳の補正に従う（この edgeId は新規なので初回は 1.96）
- 売買の合否ではない。向きが出たら、**売買として成立するかは別に事前登録して確かめる**
  （コスト36bps＋インパクト、売りなら貸借区分と貸株料）

## 1回だけ

```
pnpm research:edinet-study -- --doc-descriptions 訂正有価証券報告書 \
  --dedupe-days 60 --from 2024-06-19 --intent="<この試行で確かめること>"
```

実装の誤りを直して測り直すことは認める（理由を記録に残す）。**条件の変更は認めない。**
向きが出た場合に封印期間で確認するなら、そのときに別の事前登録を書く。
